Claim your Telegram Solana wallet

Bot-first: talk to the Telegram bot (/start) to create a Privy embedded Solana wallet. The bot is an additional signer under a Solana policy — it cannot export your private key.

App-first: log in here with Telegram (or link Telegram), then grant the bot signer. Use Phantom / Solflare / Backpack on Solana only.

PrivyProvider (Solana-only)

Drop this into a Next.js app with NEXT_PUBLIC_PRIVY_APP_ID. WalletConnect QR is desktop-only.

import {PrivyProvider} from '@privy-io/react-auth';
import {toSolanaWalletConnectors} from '@privy-io/react-auth/solana';

const solanaConnectors = toSolanaWalletConnectors({ shouldAutoConnect: true });

<PrivyProvider
  appId={process.env.NEXT_PUBLIC_PRIVY_APP_ID}
  config={{
    appearance: {
      walletList: ['phantom', 'solflare', 'backpack', 'detected_solana_wallets', 'wallet_connect_qr_solana'],
      walletChainType: 'solana-only'
    },
    embeddedWallets: { solana: { createOnLogin: 'users-without-wallets' } },
    externalWallets: { solana: { connectors: solanaConnectors } }
  }}
>
  {children}
</PrivyProvider>
Signer policy (do not invert these)
  • Allow Compute Budget, Token, ATA, Jupiter v6 — not a blanket System Program allowlist
  • SOL Transfer.lamports ≤ 0.5 SOL (matches MAX_SWAP_INPUT_AMOUNT)
  • USDC TransferChecked capped separately
  • exportPrivateKey DENY for the bot signer
  • Never add instructionName: Transfer ALLOW after the lamports cap — that override is a Privy anti-pattern
  • Address-based conditions fail if the address lives only in an Address Lookup Table
